    ⚡ System capabilities

    • Precise correction calculation: automatic comparison between the original target grid and the impact grid, producing inverted easting and northing corrections (the compensation required), rounded to multiples of 50 metres.
    • Gun traverse calculation (optional): if a gun grid is entered, the system computes azimuths and produces precise traverse commands in degrees and mils (6400). Note: a gun grid is not required for the correction itself, but it is required if you want traverse data.
    • History and task management: stores the correction sequence for a target (up to 24 hours), manages a task table, and copies reports to the clipboard. Tasks can be added directly from the interactive map, or loaded from the table (which updates both the task name and the grid).
    • Interactive map: supports picking points manually on a satellite/street map for the gun, target, impact, and for adding tasks.
    • 🗺️ Impact history on the map: the "Map" button in the correction-history panel opens a read-only graphical view showing the original target as a blue dot, every impact as a numbered red dot with its correction details on tap, and a dashed line connecting them in chronological order - so you can see the convergence toward the target visually.
    • 📥 Task list import and export: the list is imported and exported as Excel / XLSX. On import you can choose between replacing the existing list or appending to it. Backup and restore of the app data stay separate.

    ⚠️ System limitations

    • Gun range limit: automatically blocked if the distance between gun and target exceeds 7,000 metres.
    • Single correction limit: a correction over 400 metres in a single component requires resetting the target history, because it exceeds the safety radius.
    • Cumulative correction limit (550 m): if the sum of the absolute northing and easting corrections together (or the total cumulative offset) exceeds 550 metres, the system shows an error and requires the firing solution to be recomputed.
    • Data validity: target and correction history is stored locally and deleted automatically after 24 hours.
    • The only component requiring internet: the interactive map (Leaflet + map tiles), which loads only when you actually press the map button. Everything else - correction and traverse calculations, tasks, history, and Excel import/export - runs entirely locally with no network.
    • Browser requirement for Excel import/export: needs Chrome 103+, Safari 16.4+, or Firefox 113+. Excel files are read and written using built-in browser capabilities (DecompressionStream) rather than an external library, which is what makes them work fully offline. On an older browser the Excel buttons report that they are unavailable. You can check this at any time via ⚙️ Settings → Run diagnostics.

    🛠️ Step-by-step usage guide

    • Step 1 (optional): enter the firing gun grid in its field, pick it from the map, or fix it from the phone GPS. The GPS reading is not accurate and does not replace standard means of fixing a position. The grid is required only to obtain traverse corrections.
    • Step 2: enter the original target grid, or choose a prepared task from the task table / saved targets list - loading from the table updates both the task name and the grid. Alternatively add a new task by dropping a pin on the map in the tasks section. You can attach a descriptive name to the target.
    • Step 3: enter the actual impact grid in the third field (or press the "Map" button and pick the impact point).
    • Step 4: press "Cardinal correction" for east/west and north/south, or "Vector correction (sniper)" for azimuth and range to the target and to the impact, from the observer on the target at azimuth 0 and range 0.
    • Step 5: you can share the report or copy the history straight from the results panel, and press "🗺️ Map" in the history panel to see the whole impact sequence drawn on the map.
    • Step 6 (optional) - backing up the task list: in Data, export the list to Excel and import it back at any time - choosing between replacing the list or appending to it. Backup and restore of the app data stay there too.

    📊 Fixed format for importing tasks from Excel

    • File structure: first sheet only. First row = headers, remaining rows = data.
    • Three columns in fixed order: Task name | UTM grid | Ranged
    • The "Ranged" column: the value כן (or Yes) marks a ranged task. Any other value, including empty, is read as not ranged.
    • UTM grid: in the same format the calculator accepts, for example 36S E 650500 N 456700. The leading 3 in northing is optional.
    • The safe route: export a file with the "⬇️ Excel" button, edit it, and import it back - the format is guaranteed to match.
